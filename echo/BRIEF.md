# BRIEF — ECHO: сайт с проходками, QR-входом и автообновлением из TG

Рабочий документ для встречи с организатором ECHO.
Демо: **https://echo-party.vercel.app** — показывать с телефона.
Код живёт в папке `echo/` общего репозитория (Vercel-проект с Root
Directory = `echo`); прод обновляется с ветки `main`. Это отдельный
продукт со своей БД и своими env — с TRAP HOUSE ничего не пересекается.

Концепция бренда (по афише 08.08 и каналу @ECHO_BP_M): **двойной формат
в одну дату** на ул. Монтажников 2/1 (Оренбург) —
дневная тусовка **14+** (16:00–21:00, без алкоголя) и ночная **18+**
(00:00–10:00, вход бесплатный с 00:00 до 00:30). Вход 600 ₽, скидка
за репост −100 ₽. Текильщицы вместо официантов (ночь), интерактивы,
конкурсы, розыгрыши, фото-зоны, red cups. Слоган: «Собери свою компанию
и оставь след в ECHO».

## 1. Что уже есть в демо (показать вживую)

1. **Афиша двойного формата**: ECHO DAY 14+ и ECHO NIGHT 18+ отдельными
   событиями с волнами цен (ранняя 500 / на входе 600 ₽).
2. **Фри-проходка на ночную**: афишное «вход бесплатный до 00:30» оформлено
   первой волной за 0 ₽ с квотой — гость регистрируется и получает такой же
   именной QR. Организатор впервые ВИДИТ, сколько людей придёт по фри-входу,
   и считает конверсию фри → платные.
3. **Покупка за минуту**: имена гостей → телефон → согласие → именные билеты
   (сейчас оплата в демо-режиме, шлюз подключается этапом 3).
4. **QR-проходка**: сканируется обычной камерой телефона → светофор для
   админа (зелёный «Пропустить», красный «Уже использован в 01:41, впустил
   Артём» / «Подделка»). Скриншот чужого билета не проходит. Возрастная
   маркировка на экране скана: на ночной 18+ несовершеннолетний не пройдёт.
5. **Офлайн-выживаемость**: подпись без БД, офлайн-список на телефоне,
   впуск «под запись» с досинхронизацией, печатный список.
6. **Панель организатора**: продано/выручка/вошло/осталось по каждой из тус,
   онлайн/касса, продажи по дням, кривая входа, лента сканов, касса
   (ручное оформление гостя на входе), боевой самотест кнопкой.
7. **Фейсконтроль-интерактив**: «Сколько тебе лет?» → «Рано» / «Дневная
   твоя» / «Обе твои» + «скопировать и похвастаться».
8. **«Привезите к нам»**: чипы городов + заявка → уведомление в TG.
9. **Секции «Родителям» и FAQ** под двойной формат: дневная 0% алкоголя
   и домой засветло; ночная — строго 18+ по паспорту.
10. **Автообновление сайта из TG-канала** (раздел 3).

Проверено: 87 юнит/SQL-тестов (Postgres) + браузерный e2e, включая
регистрацию фри-проходки за 0 ₽ — зелёные.

## 2. Чем это сильнее текущего процесса ECHO

| Сейчас (по афише и каналу) | С платформой |
|---|---|
| Оплата на входе — очередь и наличка на дверях | Куплено заранее, вход по QR за секунды |
| Репост-скидка −100 ₽ — скрины проверяют вручную | Ранняя волна 500 ₽ даёт ту же выгоду без проверки скринов |
| «Вход бесплатный до 00:30» — сколько придёт, неизвестно | Фри-проходка с QR: список известен заранее, квота управляема |
| Списки гостей вручную в переписке | Именные билеты из формы, касса в админке для входа |
| Повторный вход и передача браслета «на глаз» | Одноразовый QR + журнал: кто, когда, кто впустил |
| Выручку и посещаемость никто не видит | Панель + все данные в БД под TG-бота владельца |
| Афиша живёт только постами в канале | Сайт обновляется сам при посте в канале |

## 3. Автообновление из канала @ECHO_BP_M (как включить)

Пост в канале → анализ (LLM) → черновик события в БД → владельцу в TG
приходит превью с кнопками **«Опубликовать / Пропустить»** → одна кнопка,
и событие на сайте (redeploy не нужен). `AUTO_PUBLISH=1` — полный автопилот.
Афиша-картинка поста подтягивается автоматически. Без LLM-ключей посты
просто пересылаются владельцу с пометкой «обнови вручную».

Анализатор знает специфику ECHO: двойной формат в одну дату, площадку
Монтажников 2/1 и допускает цену 0 ₽ (фри-вход).

Настройка (5 минут, после env из раздела 7):
1. Добавить бота (того же, чей `TELEGRAM_BOT_TOKEN`) **администратором
   канала** @ECHO_BP_M (права «читать сообщения» достаточно).
2. Зарегистрировать вебхук (одна команда, подставить свои значения):
   `curl "https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://<домен>/api/tg-webhook&secret_token=<TG_WEBHOOK_SECRET>"`
3. Готово: каждый новый пост канала попадает в конвейер мгновенно.

**Провайдер анализа — Polza AI** (российский OpenAI-совместимый агрегатор,
оплата в рублях, ключ на polza.ai): env `POLZA_API_KEY` + опционально
`POLZA_MODEL` (по умолчанию `openai/gpt-4o-mini`) и `POLZA_BASE_URL`
(по умолчанию `https://api.polza.ai/api/v1`). `ANTHROPIC_API_KEY` —
необязательный фолбэк. Экономика при 1–2 постах в день — порядка 1 ₽/мес
даже на полноразмерных моделях (пост ≤3000 символов, max_tokens 700,
один вызов на пост, повторы отсекаются по update_id).

## 4. Вопросы владельцу ECHO (★ — блокируют боевой запуск)

1. ★ Даты ближайших тус (сид сейчас — правдоподобные заглушки
   ECHO DAY 29.08 и ECHO NIGHT 30.08; прошедшая ECHO X 08.08).
2. ★ Как сейчас принимают деньги; целевой провайдер онлайн-оплаты
   (ЮKassa / СБП). Реквизиты ИП для политики ПД и кассы 54-ФЗ.
3. ★ Куда слать уведомления о продажах и кнопки публикации (chat_id
   владельца/менеджера); кто менеджер по билетам (сейчас заглушка —
   ссылка на канал).
4. ★ Домен: покупаем короткий (компактнее QR)? Ссылка VK, если есть.
5. Репост-скидка −100 ₽: закрываем ранней волной 500 ₽ (как в демо)
   или нужна отдельная механика с проверкой репоста?
6. Квота фри-входа на ночную (в демо 150) и лимиты по волнам.
7. Афиша 08.08 и фото с тус — прислать для сайта (постеры событий,
   фотолента, og-превью; сейчас стилизованные заглушки).
8. Автопилот публикации: сразу AUTO_PUBLISH=1 или сперва с подтверждением?
9. Логотип/шрифтовый знак — есть ли исходники.

## 7. Технический паспорт (запуск)

Стек: статика + ES-модули (без сборки) · Vercel serverless · Neon Postgres ·
LLM-анализ постов (Polza AI / Anthropic).

Vercel-проект: `echo-party`, Root Directory = `echo` (папка в общем
репозитории). Продакшен собирается с ветки `main`.

Env-переменные (Vercel → echo-party → Settings → Environment Variables) —
свои, от TRAP HOUSE ничего не переиспользовать:
`DATABASE_URL` (СВОЯ Neon-база из Marketplace) · `TICKET_SECRET` (32+
случайных символов, другой, чем у TRAP HOUSE) · `ADMIN_KEY` (ключ админов
входа) · `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` (уведомления и кнопки;
бот может быть отдельный) · `TG_WEBHOOK_SECRET` (для вебхука канала) ·
`POLZA_API_KEY` (анализ постов; `POLZA_MODEL`, `POLZA_BASE_URL` —
опциональные переопределения) · опционально `ANTHROPIC_API_KEY` (фолбэк),
`AUTO_PUBLISH=1`, `BOT_API_TOKEN`, `TICKET_SECRET_OLD`.

**Подключение БД (Neon, 3 шага):**
1. Vercel → проект echo-party → вкладка **Storage** → **Create Database →
   Neon** (Free plan) → **Connect to project** — `DATABASE_URL` добавится сам.
2. **Redeploy** (Deployments → ⋯ у последнего → Redeploy), чтобы функции
   увидели новые переменные.
3. Открыть `/admin.html` → ввести `ADMIN_KEY` → кнопка **«Инициализировать
   БД»** (галочка «посеять демо-продажи» — для показа; снять — для боя).
   Нюанс показа: демо-продажи «разбирают» фри-квоту ночной (реалистичный
   ажиотаж) — чтобы показать кнопку «Взять фри-проходку», сейте без
   демо-продаж.
   Эквивалент curl: `curl -X POST https://<домен>/api/seed -H "X-Admin-Key: <ключ>"
   -H "Content-Type: application/json" -d '{"demoSold":true}'`

**Боевой самотест** — кнопка в `/admin.html`: прогоняет на проде весь цикл
(покупка → билет → верификация → чек-ин → повтор отклонён → статистика →
уборка тестовых данных с возвратом квот) и рисует чек-лист. Ключ при этом
не покидает устройство. Повторять можно сколько угодно.

Афиша правится: постом в канале (конвейер) или в `assets/data/events.js` +
seed. Волна с ценой 0 = фри-регистрация: кнопка сама становится
«Получить проходку · фри», плашка про демо-оплату скрывается.

Тесты: `npm test` (внутри `echo/`). Локально без Neon: `DEV_PGLITE=1`
(настоящий Postgres в памяти). Деградации: без БД — сид + TG-фолбэк заказа;
без LLM — пересылка постов; без TG — сайт работает, уведомлений нет.
Ошибок гость не видит нигде.

**Секреты:** только в env. Ключ, засветившийся в переписке, — перевыпустить.
