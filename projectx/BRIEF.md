# BRIEF — PROJECT X: сайт с проходками, QR-входом и афишей из админки

Рабочий документ для встречи с организатором.
Демо: **https://projectx-party.vercel.app** — показывать с телефона.
Код живёт в папке `projectx/` общего репозитория (Vercel-проект с Root
Directory = `projectx`); прод обновляется с ветки `main`. Отдельный продукт
со своей БД и своими env — с TRAP HOUSE и ECHO ничего не пересекается.

Концепция бренда (снята с реальных афиш @project.x.prty): **ночные вечеринки
строго 18+** в Оренбурге, **FC/DC** (фейсконтроль и дресс-код), **двери 22:00,
старт 23:00**, финиш под утро. Фирменная фишка — **SECRET PLACE**: площадка
объявляется позже, адрес приходит в проходке. Ядро аудитории — студенты
(посвящение первокурсников, ночь студента, Хэллоуин, американ-пати с red cups
и free bar). У бренда есть второй аккаунт (@project.x.tolyatti), но по
решению заказчика сайт пока только про Оренбург — Тольятти нигде не упоминается.

## 1. Главный аргумент: Instagram в РФ заблокирован

Аккаунт бренда живёт за VPN. Практические следствия, которые видно по нашей
же разведке (15+ поисковых запросов, все зеркала — Picuki, Imginn и прочие):
**из открытого интернета о PROJECT X нельзя узнать вообще ничего** — ни имени,
ни афиши, ни цен. Поисковику Instagram отдаёт только страницу входа.

Сайт закрывает эту дыру: он индексируется, открывается без VPN у кого угодно
(включая родителей, партнёров и площадки), и принимает деньги. Instagram
остаётся витриной для своих, сайт — точкой входа для всех остальных.

Отдельно: по запросу «project x вечеринка» вся выдача принадлежит чужим
брендам — московскому PROJECT X (дневные пати для школьников, TimePad) и
франшизе «PROJECT X | Проект икс» (18+ с безлимитным алкоголем, 8+ городов).
Свой сайт с привязкой к городу («PROJECT X Оренбург» в title и OG) —
единственный способ не потеряться среди них. Это же довод за короткий
собственный домен: связка «prty» уже занята чужой франшизой.

## 2. Что уже есть в демо (показать вживую)

0. **Кинематографичная главная**: полноэкранный знак PROJECT X, который живёт
   под курсором и наклоняется на прокрутке; сцена «три правила ночи» (18+ /
   FC/DC / SECRET PLACE) раскрывается по мере скролла; лента прошедших афиш
   листается как стопка постеров; манифест в три фразы. Вторичные разделы
   (правила, FAQ, контакты) вынесены на отдельные страницы — главная короткая
   и ведёт к одному действию: взять проходку. Всё движение уважает системную
   настройку «меньше движения».
1. **Афиша ночных событий** с волнами цен (400 ранняя / 600 вторая / 800 на входе).
2. **Проходка за минуту**: имена гостей → телефон → согласие → именные QR
   (сейчас демо-режим оплаты: деньги не списываются, механика видна целиком).
3. **QR-вход**: сканируется обычной камерой телефона → светофор для админа
   (зелёный «Пропустить», красный «Уже использован в 01:41, впустил Артём» /
   «Подделка»). Скриншот чужой проходки не проходит.
4. **Возраст**: все события 18+, несовершеннолетним проходка не продаётся —
   попытка отсекается на сервере, а не «на честном слове».
5. **Офлайн-выживаемость**: подпись без БД, офлайн-список на телефоне, впуск
   «под запись» с досинхронизацией, печатный список.
6. **Панель организатора**: продано/выручка/вошло/осталось, онлайн vs касса,
   продажи по дням, кривая входа, лента сканов, касса на дверях (ручное
   оформление гостя), боевой самотест кнопкой.
7. **★ Афиша из админки** — ключевая фича именно для PROJECT X (раздел 3).
8. **Фейсконтроль-интерактив** («Сколько тебе лет?» → «Рано» / «Проходишь»)
   и «Привезите к нам» — заявки из других городов.
9. **Правила входа и FAQ** под ночной формат: паспорт, дресс-код, браслет,
   передача проходки, возврат — на отдельных страницах /rules и /faq
   (аккордеон с плавным раскрытием).

Проверено: 104 юнит/SQL-теста (настоящий Postgres) + браузерный e2e из 55
шагов, включая сцену «три правила», мобильное меню, страницы второго уровня,
создание события из панели и покупку на нём — всё зелёное.

## 3. ★ Афиша из админки (вместо автообновления из канала)

У TRAP HOUSE афиша обновляется постами Telegram-канала. У PROJECT X канала
нет, поэтому источником стала сама панель: раздел **«События»** —
создать вечеринку, задать дату, двери/финиш, площадку, описание и волны цен,
нажать «Сохранить» — сайт обновился. Никакого разработчика и редеплоя.

Что предусмотрено, чтобы владелец не сломал продажи:
- **Черновик** (статус «черновик») виден только в панели — можно готовить
  вечеринку заранее и опубликовать одной сменой статуса;
- **квота не опускается ниже проданного** — сервер поднимает её обратно и
  говорит об этом («уже продано 12 — квота поднята до 12»);
- **волну с продажами нельзя удалить** — на неё ссылаются заказы гостей;
- **id события не меняется** при правках — уже выданные QR продолжают работать;
- **ночь через полночь** (23:00 → 06:00) считается правильно: финиш
  автоматически уезжает на следующий день, время всегда в поясе площадки.

Конвейер анализа постов из кода не убран: если у бренда появится Telegram-канал,
он включается парой env-переменных (`TELEGRAM_BOT_TOKEN`, `TG_WEBHOOK_SECRET`,
`POLZA_API_KEY`) и одной командой `setWebhook` — сейчас он просто спит.

## 7. Технический паспорт (запуск)

Стек: статика + ES-модули (без сборки) · Vercel serverless · Neon Postgres.
Vercel-проект: `projectx-party`, Root Directory = `projectx`, продакшен с `main`.

Env-переменные (Vercel → projectx-party → Settings → Environment Variables) —
**свои, ничего от TRAP HOUSE и ECHO не переиспользовать**:
`DATABASE_URL` (СВОЯ база Neon) · `TICKET_SECRET` (32+ случайных символов,
свой) · `ADMIN_KEY` (ключ входа в панель и сканер) · опционально
`TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` (уведомления о продажах),
`TG_WEBHOOK_SECRET` + `POLZA_API_KEY` (спящий конвейер из канала),
`AUTO_PUBLISH=1`, `BOT_API_TOKEN`, `TICKET_SECRET_OLD`.

**Подключение БД (Neon, 3 шага):**
1. Vercel → проект → **Storage → Create Database → Neon** (Free) →
   **Connect to project** — `DATABASE_URL` добавится сам.
2. **Redeploy** (Deployments → ⋯ → Redeploy), чтобы функции увидели переменные.
3. `/admin.html` → ввести `ADMIN_KEY` → **«Инициализировать БД»**
   (галочка «посеять демо-продажи» — для показа; снять — для боя).
   Эквивалент curl: `curl -X POST https://<домен>/api/seed -H "X-Admin-Key: <ключ>"
   -H "Content-Type: application/json" -d '{"demoSold":true}'`

**Боевой самотест** — кнопка в `/admin.html`: прогоняет на проде весь цикл
(покупка → проходка → верификация → чек-ин → повтор отклонён → статистика →
уборка тестовых данных) и рисует чек-лист из 9 шагов. Ключ не покидает
устройство, повторять можно сколько угодно.

Афиша правится в разделе «События» админки (раздел 3) или в
`assets/data/events.js` + повторный сид.

Тесты: `npm test` внутри `projectx/`. Локально без Neon: `DEV_PGLITE=1`
(настоящий Postgres в памяти). Деградации: без БД — сид + фолбэк оформления
в директ; без TG — сайт работает, уведомлений нет. Ошибок гость не видит нигде.

Ограничение хостинга: сейчас 12 serverless-функций — ровно потолок тарифа
Vercel Hobby. Следующий эндпоинт (реальная оплата, этап 2) потребует Pro
или объединения функций.

**Секреты:** только в env. Ключ, засветившийся в переписке, — перевыпустить.
